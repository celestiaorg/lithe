# Standard library

The standard library ships inside the compiler. Import a module with a path that starts with `std/`:

```lithe
import "std/token/erc20.lithe";
import "std/access/ownable.lithe";

contract Token is {
  use ERC20;
  use Ownable;

  storage is record {
    minted : nat;
  }

  deploy()
    raises OwnableInvalidOwner
  is {
    ERC20.init("Token", "TKN");
    Ownable.init(Evm.sender());
  }

  external view function balanceOf is ERC20.balance_of;
  external function transfer is ERC20.transfer;

  external function mint(const to : address; const value : nat)
    raises OwnableUnauthorizedAccount | ERC20InvalidReceiver | ERC20InsufficientBalance
  is {
    Ownable.check_owner();
    ERC20.mint(to, value);
    storage.minted := storage.minted + value;
  }
}
```

Every module follows the ordinary rules for [modules](/language/modules):

- **Module functions are internal.** A contract exposes what it wants, either by promotion (`external function transfer is ERC20.transfer;`) or by writing its own entrypoint. A promotion can rename: module functions are `snake_case`, and a token promotes them under the standard's ABI names, `balanceOf` from `ERC20.balance_of`.
- **Each module owns its storage**, at an ERC-7201 root named `lithe.std.<module>`: `lithe.std.erc20`, `lithe.std.ownable`, and so on. Contracts don't redeclare a module's schema, and two modules never collide.
- **Extensions add behavior, and never change a base module silently.** A pause, a cap, or a fee is written in the contract's own `transfer`, around the module's pieces.
- **Errors and events match OpenZeppelin's**, so wallets, explorers, and indexers decode them as they already do.

## What isn't here

- **A reentrancy guard.** [`nonreentrant`](/language/reentrancy) is a language feature, and deferred calls already run after a transition's own effects.
- **Byte and arithmetic primitives.** `Bytes.concat`, `Bytes.word`, `Nat.mul_div`, and the rest are [built-ins](/language/builtins), because the compiler does them better than a library could.
- **ERC-1155.** Not yet. The interface, batch methods included, is in `std/interfaces/erc1155.lithe`.
- **Applications**, such as AMMs, lending markets, or auctions. They are too opinionated for a foundation.
