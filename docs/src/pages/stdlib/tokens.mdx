# Tokens

## `ERC20`

`std/token/erc20.lithe`. The ERC-20 standard, with OpenZeppelin's errors, events, and order of checks. A token promotes the standard functions under their ABI names:

```lithe
import "std/token/erc20.lithe";

contract Token is {
  use ERC20;

  storage is record {
    minter : address;
  }

  deploy(const supply : nat)
    raises ERC20InvalidReceiver | ERC20InsufficientBalance
  is {
    ERC20.init("Token", "TKN");
    ERC20.mint(Evm.sender(), supply);
  }

  external view function name is ERC20.name;
  external view function symbol is ERC20.symbol;
  external pure function decimals is ERC20.decimals;
  external view function totalSupply is ERC20.total_supply;
  external view function balanceOf is ERC20.balance_of;
  external view function allowance is ERC20.allowance;
  external function transfer is ERC20.transfer;
  external function approve is ERC20.approve;
  external function transferFrom is ERC20.transfer_from;
}
```

| Function | |
| --- | --- |
| `init(name, symbol)` | |
| `name()`, `symbol()`, `decimals()`, `total_supply()`, `balance_of(a)`, `allowance(o, s)` | views; `decimals` is 18 |
| `transfer(to, value)`, `approve(spender, value)`, `transfer_from(from, to, value)` | the standard's entrypoints, for promotion |
| `move(from, to, value)` | a checked transfer between two accounts |
| `mint(account, value)`, `burn(account, value)` | |
| `update(from, to, value)` | every balance change; `from` zero mints, `to` zero burns |
| `approve_as(owner, spender, value, announce)` | sets an allowance, logging `Approval` if `announce` |
| `spend_allowance(owner, spender, value)` | an allowance of `Nat.max` is never spent down |

To add a rule, write the entrypoint yourself around `move` and `spend_allowance`:

```lithe fragment
external function transfer(const to : address; const value : nat) : bool
  raises EnforcedPause | ERC20InvalidSender | ERC20InvalidReceiver | ERC20InsufficientBalance
is {
  Pausable.require_not_paused();
  ERC20.move(Evm.sender(), to, value);
} with true
```

## `ERC20Burnable`

`std/token/erc20_burnable.lithe`. `burn(value)` burns the caller's tokens, and `burn_from(account, value)` spends an allowance to burn someone else's.

## `ERC20Permit`

`std/token/erc20_permit.lithe`. ERC-2612: approvals signed off-chain, so a holder can approve without paying for a transaction. It uses [`EIP712`](/stdlib/crypto#eip712), [`ECDSA`](/stdlib/crypto#ecdsa), and [`Nonces`](/stdlib/utils#nonces), and a contract uses all four:

```lithe
import "std/token/erc20_permit.lithe";

contract Token is {
  use ERC20;
  use EIP712;
  use ECDSA;
  use Nonces;
  use ERC20Permit;

  storage is record {
    supply_cap : nat;
  }

  deploy() is {
    ERC20.init("Token", "TKN");
    EIP712.init("Token", "1");
  }

  external view function balanceOf is ERC20.balance_of;
  external view function allowance is ERC20.allowance;
  external function transferFrom is ERC20.transfer_from;
  external function permit is ERC20Permit.permit;
  external view function nonces is Nonces.nonces;
  external view function DOMAIN_SEPARATOR is EIP712.domain_separator;
}
```

## `ERC721`

`std/token/erc721.lithe`. The ERC-721 standard and its metadata extension, with OpenZeppelin's errors, events, and order of checks. The safe transfers and `safe_mint` call the receiver in a [deferred call](/language/effects), after the transfer's own effects, and pass on a receiver's revert reason unchanged.

```lithe
import "std/token/erc721.lithe";

contract Collection is {
  use ERC721;

  storage is record {
    next_id : nat;
  }

  deploy() is {
    ERC721.init("Collection", "COL");
  }

  external pure function supportsInterface is ERC721.supports_interface;
  external view function balanceOf is ERC721.balance_of;
  external view function ownerOf is ERC721.owner_of;
  external view function getApproved is ERC721.get_approved;
  external view function isApprovedForAll is ERC721.is_approved_for_all;
  external function approve is ERC721.approve;
  external function setApprovalForAll is ERC721.set_approval_for_all;
  external function transferFrom is ERC721.transfer_from;
  external function safeTransferFrom is ERC721.safe_transfer_from;
  external function safeTransferFrom is ERC721.safe_transfer_from_with_data;

  external function mint() : nat
    raises ERC721InvalidReceiver | ERC721InvalidSender | ERC721NonexistentToken | ERC721InsufficientApproval
  is {
    const id : nat := storage.next_id;
    storage.next_id := id + 1n;
    ERC721.safe_mint(Evm.sender(), id, "");
  } with id
}
```

Both `safeTransferFrom` overloads are promoted under one name, because their ABI signatures differ. `token_uri` checks that the token exists and answers the empty string, as OpenZeppelin's does without a base URI; a collection with URIs writes its own `tokenURI`.
