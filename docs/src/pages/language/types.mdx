# Types

Lithe is statically typed. Every local binding names its type, and nothing converts implicitly: not between widths, not between `nat` and `int`, and not between a nominal type and its representation.

## Primitive types

| Type | ABI type | Values |
| --- | --- | --- |
| `bool` | `bool` | `true`, `false` |
| `nat` | `uint256` | unsigned 256-bit integers. `uint256` is another name for `nat` |
| `int` | `int256` | signed 256-bit integers. `int256` is another name for `int` |
| `uint8` ... `uint248` | same | unsigned integers of that width, in steps of 8 |
| `int8` ... `int248` | same | signed integers of that width, in steps of 8 |
| `address` | `address` | 20-byte account addresses |
| `bytes1` ... `bytes32` | same | fixed-size byte strings |
| `bytes` | `bytes` | dynamic byte strings |
| `string` | `string` | UTF-8 text |
| `wei` | `uint256` | an amount of ether |
| `timestamp` | `uint256` | a point in time, in Unix seconds |
| `unit` | (nothing) | the result of a function that returns nothing |

### Integers

Arithmetic on every integer type is checked. Overflow, underflow, and narrowing out of range revert with `Panic(0x11)`, and division by zero reverts with `Panic(0x12)`, as in Solidity. Each fixed width is its own type: a `uint8` does not mix with a `uint16` or a `nat` without an explicit conversion.

Where wrapping is the point, as for a price accumulator meant to overflow, name it: `Nat.wrapping_add`, `Nat.wrapping_sub`, and `Nat.wrapping_mul` take two values of one unsigned type and keep the result's low bits, as Solidity's `unchecked` arithmetic does. `Int.wrapping_*` do the same for signed types. See [Built-ins](/language/builtins#nat-int-and-address).

```lithe
storage is record {
  small : uint8;
  total : nat;
}

external function add(const a : uint8; const b : nat) is {
  storage.small := a + 1;
  storage.total := nat(a) + b;
}
```

### Semantic types: `wei` and `timestamp`

`wei` and `timestamp` are `uint256` in the ABI, but the type checker keeps them apart from `nat` and from each other, so a price is never added to a deadline by mistake.

| Expression | Type |
| --- | --- |
| `wei + wei`, `wei - wei` | `wei` |
| `wei * 2`, `wei / 2` (literal) | `wei` |
| `timestamp + duration`, `timestamp + nat` | `timestamp` |
| `timestamp - timestamp` | `nat` (seconds) |
| `Evm.value()`, `Evm.balance(a)` | `wei` |
| `Evm.block_timestamp()` | `timestamp` |

Ether literals such as `1eth` and `3gwei` are `wei`. Duration literals such as `2days` are durations. See [Literals and units](/language/literals).

## Conversions

Convert with the target type's name, used as a function:

```lithe
storage is record {
  n : nat;
}

external pure function convert(const x : uint8; const raw : bytes20; const amount : nat) : (nat, address, uint16, wei) is
  (nat(x), address(raw), uint16(amount), wei(amount))
```

| Conversion | Behavior |
| --- | --- |
| to a wider integer (`nat(x)` for `x : uint8`) | always succeeds |
| to a narrower integer (`uint8(n)`) | checked, `Panic(0x11)` if out of range |
| between signed and unsigned of a smaller width (`int16(x)`) | checked |
| between `nat` and `int` | reinterprets the 256 bits, as in Solidity |
| `address(b)` for `b : bytes20`, and `bytes20(a)` | exact |
| `nat(b)` for `b : bytes32`, `uint32(s)` for `s : bytes4`, and back: `bytesN` and the unsigned integer of the same width | exact |
| `uint160(a)` for `a : address`, and `address(u)` for `u : uint160` | exact |
| `Token(a)` for an interface `Token`, and `address(t)` | exact |
| `wei(n)`, `timestamp(n)`, `nat(w)` | exact |
| to or from a [nominal type](#nominal-types) | exact |

## Records

A record is a struct: a fixed set of named, typed fields.

```lithe
type position is record {
  owner : address;
  amount : nat;
  opened_at : timestamp;
}

storage is record {
  positions : map(nat, position);
}

external function open(const id : nat; const amount : nat) is {
  storage.positions[id] := {
    owner = Evm.sender();
    amount = amount;
    opened_at = Evm.block_timestamp();
  };
}

external function grow(const id : nat; const extra : nat) is {
  storage.positions[id].amount := storage.positions[id].amount + extra;
}
```

A record literal is `{ field = value; ... }`. It takes its type from where it is used, such as a binding's annotation, a storage field, or a parameter. In the ABI, a record parameter or return value is flattened into its fields, like a Solidity getter for a struct.

A record's fields can be strings, bytes, and dynamic lists too. An external function that returns such a record returns its fields in order, each dynamic one after an offset, as a Solidity function with several results does:

```lithe
type domain is record {
  fields : bytes1;
  name : string;
  chainId : nat;
  extensions : list(nat);
}

storage is record {
  name : string;
}

external view function eip712Domain() : domain is {
  const extensions : list(nat) := [];
} with {
  fields = 0x0f;
  name = storage.name;
  chainId = Evm.chain_id();
  extensions = extensions;
}
```

## Tuples

Tuples group values by position. Destructure them in a `const` binding:

```lithe fragment
pure function split(const amount : nat) : (nat, nat) is
  (amount / 2n, amount - amount / 2n)

const (half, rest) : (nat, nat) := split(amount);
```

A function that returns several values returns a tuple. Tuples nest, can be stored, and pack in storage like a struct.

## Lists

`list(T)` is a dynamic list and `list(T, n)` is a fixed list of length `n`.

```lithe
storage is record {
  history : list(nat);
  top3 : list(address, 3);
}

external function push(const value : nat) is {
  storage.history[storage.history.length] := value;
  storage.top3[0n] := Evm.sender();
}

external pure function third() : nat is {
  const primes : list(nat, 4) := [2n, 3n, 5n, 7n];
} with primes[2]
```

- `xs[i]` reads and `xs[i] := v` writes. Writing to a dynamic list at index `length` appends.
- `List.pop(xs);` drops a dynamic list's last element. A stored list clears the element's slots, as Solidity's `pop` does. An empty list reverts with `Panic(0x31)`.
- `xs.length` is the length of a dynamic list.
- Any other index past the end reverts with `Panic(0x32)`.
- Elements are single words, or fixed-size records, tuples, or [options](#options).

A list of records is a Solidity array of structs. In storage each element starts a slot and packs its fields as a struct does, so a record of a `uint48` and a `uint208` takes one slot. A field of an element reads and writes in place:

```lithe
type checkpoint is record {
  key : uint48;
  value : uint208;
}

storage is record {
  history : list(checkpoint);
}

external function note(const value : uint208) is {
  storage.history[storage.history.length] := { key = uint48(Evm.block_number()); value = value; };
}

external function bump(const i : nat) is {
  storage.history[i].value := storage.history[i].value + 1;
}

external view function all() : list(checkpoint) is
  storage.history
```

A dynamic list is also a value. It can be a parameter or a result, a `const` or a `var`, and it moves to and from storage whole:

```lithe
storage is record {
  saved : list(nat);
}

external function save(const xs : list(nat)) is {
  storage.saved := xs;
}

external view function saved() : list(nat) is
  storage.saved

external pure function pair(const a : nat; const b : nat) : list(nat) is {
  var out : list(nat) := [a];
  out[1n] := b;
} with out
```

- In the ABI, `list(T)` is `T[]` and `list(T, n)` is `T[n]`, and a list of records is an array of tuples, `(uint48,uint208)[]`. A list argument is checked as Solidity checks one: its offset and length must lie inside the calldata, and each element must hold a value of its type.
- Assigning a list to storage replaces the stored list, and clears the slots a shorter list no longer uses.
- Reading a stored list as a value copies it. So does reading a `var`'s list, so two names never share one list: changing a `var` can't change anything else.
- `a = b` compares two lists element by element.
- Lists can be `Abi.encode`d and `Abi.decode`d, sent to and returned from other contracts, and logged in events.

## Maps

`map(K, V)` is a Solidity mapping. It exists only in storage. A key that was never written reads as the zero value, and a key is cleared by writing the zero value.

```lithe fragment
storage is record {
  balances : map(address, nat);
  allowances : map(address, map(address, nat));
}

storage.allowances[owner][spender] := amount;
```

Keys must be single-word values: integers, `bool`, `address`, `bytesN`, `wei`, `timestamp`, or nominal types over them. Values are words, maps, lists, records, or [options](#options). A record value may hold maps, lists, and strings of its own, as a Solidity struct in a mapping does, and each sits at the slot Solidity gives it:

```lithe
type role is record {
  members : map(address, bool);
  admin : bytes32;
}

storage is record {
  roles : map(bytes32, role);
  deposits : map(address, list(nat));
}

external function grant(const r : bytes32; const who : address) is {
  storage.roles[r].members[who] := true;
}

external function deposit(const amount : nat) is {
  storage.deposits[Evm.sender()][storage.deposits[Evm.sender()].length] := amount;
}

external view function deposits(const who : address) : list(nat) is
  storage.deposits[who]
```

A map's list, or a list inside a map's record, is a list in every way: it can be read and written whole, indexed, appended to, and popped with `List.pop`.

## Options

`option(T)` holds `Some(value)` or `None`. Read it with `case`:

```lithe
storage is record {
  admin : option(address);
}

external function appoint() is {
  storage.admin := Some(Evm.sender());
}

external view function admin_or_zero() : address is
  case storage.admin of {
  | Some(who) -> who
  | None -> Address.zero
  }
```

`T` can be any single word, including `string` and `bytes`, or any fixed-size value: a record, a tuple, a fixed list, or another option. A tuple payload destructures in its arm: `| Some((a, b)) -> a + b`.

### Where options work

An option works anywhere a value does, except the ABI:

- storage and transient storage fields, map values, and list elements, both stored and local, fixed and dynamic
- `const` and `var` locals, and the parameters and results of internal functions
- tuple elements and record fields
- `case` on any option, including a function's result: `case find(id) of { ... }`
- `=` and `<>`: `storage.admin = None`, or `a = Some(5n)`

A map key that was never written, an unwritten list element, and a transient field in a new transaction all read as `None`. So a map of options tells "never set" apart from "set to zero" at no extra storage cost:

```lithe
storage is record {
  expiry : map(address, option(uint64));
}

external function grant(const who : address; const expiry : uint64) is {
  storage.expiry[who] := Some(expiry);
}

external function revoke(const who : address) is {
  storage.expiry[who] := None;
}

external view function has_grant(const who : address) : bool is
  storage.expiry[who] <> None

external view function expiry_or_zero(const who : address) : nat is
  case storage.expiry[who] of {
  | Some(expiry) -> nat(expiry)
  | None -> 0
  }
```

`Some(x)` usually takes its type from where it is used. With nothing to go by, as in `case Some(x) of`, it takes the type of `x`. `None` always needs a known option type.

### Where options don't work

- **The ABI.** External parameters and results, event fields, error payloads, interface methods, and `Abi.encode` can't carry an option, even inside a tuple, record, or list. Expose a view that returns a plain value, or a `bool` for "is set".

  ```lithe rejects
  storage is record {
    limit : option(nat);
  }

  external function set_limit(const limit : option(nat)) is {
    storage.limit := limit;
  }
  ```

  ```text
  an option cannot be an ABI value
  ```

- **Map keys.** A key is always a single word.
- **Dynamic payloads inside other values.** `option(string)` and `option(bytes)` work as a storage field or a local. They can't be a map value, a list element, a tuple element, a record field, or a transient field, and they can't be compared with `=`. `T` can't be a map or a dynamic list.

### Representation

When `T` is narrower than a word, the option takes **one word**. That covers `bool`, `address`, interfaces, `uintN` and `intN` below 256 bits, and `bytesN` below 32. `None` is zero. `Some(x)` stores `x` bitwise-inverted, or for a signed `intN`, with bit N−1 flipped, so it's never zero. `Some(0)` and `None` stay distinct.

Otherwise the option takes a **tag word**, 1 for `Some` and 0 for `None`, followed by the payload's words. `None` zeroes every word.

Each word of an option is a whole slot. An option never shares a slot with the fields around it:

```text
storage
  owner: address          slot 0, offset 0, 20 bytes
  admin: option(address)  slot 1
  limit: option(uint256)  slots 2-3
  paused: bool            slot 4, offset 0, 1 byte
```

In a map or a dynamic list, an option's words take consecutive slots, as a Solidity struct does. `map(K, option(nat))` keeps a key's tag at `keccak256(key . slot)` and its payload in the slot after. Element `i` of a `list(option(nat))` starts at `keccak256(slot) + 2i`.

## Variants

A variant type is a closed set of cases, where each case may carry a payload:

```lithe fragment
type action is
  | Deposit of nat
  | Withdraw of nat
  | Close
```

In the current compiler, variants describe **entrypoint dispatch**. An external function that takes a variant exposes one ABI function per case, and matches on it with `case`. The compiler checks that the match covers every case. Variant values cannot yet be constructed in expressions or stored. See [Entrypoint dispatch](/language/dispatch).

## Nominal types

`type name is T` declares a **new** type with `T`'s representation. It does not mix with `T`, or with any other type declared over `T`:

```lithe
type basis_points is uint16;
type discount_rate is uint16;

storage is record {
  fee : basis_points;
}

external function set_fee(const fee : basis_points) is {
  storage.fee := fee;
}

external view function as_discount() : discount_rate is
  discount_rate(uint16(storage.fee))
```

A nominal type costs nothing at runtime, and in the ABI it appears as its representation. Integer literals take on nominal integer types directly: `const fee : basis_points := 500;`. A suffixed literal such as `500n` is a `nat`, and it does not.

```lithe rejects
type basis_points is uint16;
type discount_rate is uint16;

storage is record {
  n : nat;
}

external function go() is {
  const fee : basis_points := 500;
  const discount : discount_rate := fee;
  skip
}
```

```text
initializer type does not match its annotation
```

## Interface types

An [interface](/language/effects#interfaces) is a type whose values are contract addresses, typed by the methods they support. It is an `address` in the ABI and in storage.

```lithe fragment
interface Token is {
  view function balanceOf(owner : address) : nat;
  function transfer(to : address; amount : nat) : bool;
}

storage is record {
  token : Token;
}
```
