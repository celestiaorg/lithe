# Program structure

## A file is a contract

The simplest Lithe program is a file of top-level declarations. The file is the contract:

```lithe
storage is record {
  owner : address;
}

external function claim() is {
  storage.owner := Evm.sender();
}
```

To name the contract, or to put several contracts in one file, wrap each in `contract Name is { ... }`:

```lithe
contract Registry is {
  storage is record {
    count : nat;
  }

  external function register() is {
    storage.count := storage.count + 1n;
  }
}
```

A file uses either top-level declarations or explicit `contract` blocks, never both. `lithe compile file.lithe` needs a file with exactly one contract. `lithe compile directory` builds every contract in every file and writes one artifact per contract.

## Declarations

A contract is made of these declarations, in any order. Names are resolved across the whole file, so a function can use a type declared below it.

| Declaration | Example | See |
| --- | --- | --- |
| Storage | `storage is record { ... }` | [Storage](/language/storage) |
| Named storage | `storage config at "app.config" is record { ... }` | [Storage](/language/storage#named-storage) |
| Transient storage | `transient storage is record { ... }` | [Storage](/language/storage#transient-storage) |
| Type | `type order_id is bytes32;` | [Types](/language/types) |
| Error | `error Not_owner;` | [Errors](/language/errors) |
| Error set | `errors admin_errors is \| Not_owner \| Paused` | [Errors](/language/errors#error-sets) |
| Event | `event Paid of record { ... }` | [Events](/language/events) |
| Interface | `interface Token is { ... }` | [Queries and deferred calls](/language/effects) |
| Function | `external function f() is { ... }` | [Functions](/language/functions) |
| Module | `module Ledger is { ... }` | [Modules](/language/modules) |
| Use | `use Ledger;` | [Modules](/language/modules) |
| Import | `import "./lib.lithe";` | [Imports](/language/imports) |
| Upgrades | `upgradeable`, `upgrade guard is { ... }`, `migrate f() is { ... }` | [Upgrades](/language/upgrades) |
| Receive and fallback | `payable receive is { ... }`, `fallback is { ... }`, `fallback delegates to target;` | [Functions](/language/functions#receive-and-fallback) |

Every contract declares `storage is record`, even an empty one, and at least one external function:

```lithe
storage is record {}

external pure function version() : nat is
  1n
```

## Comments

Comments are written `(* like this *)`. They can span lines, and they nest, so you can comment out code that already contains comments.

```lithe fragment
(* A comment.
   (* A nested comment. *)
   Still inside the outer comment. *)
```

There are no line comments.

## Punctuation

Each bracket has one job:

| Bracket | Used for |
| --- | --- |
| `( )` | grouping, calls, parameters, tuples |
| `[ ]` | list literals, indexing, map lookup |
| `{ }` | records, blocks, `case` arms, interfaces, modules, contracts |

Statements end with `;`. Fields in a record type or record literal also end with `;`. Parameters are separated by `;`, and arguments by `,`:

```lithe fragment
pure function scale(const amount : nat; const bps : nat) : nat is
  amount * bps / 10_000n

const fee : nat := scale(1_000n, 25n);
```

## Naming

Lithe does not enforce a naming style, but its examples and standard modules follow these conventions:

| Kind | Convention | Example |
| --- | --- | --- |
| Types, functions, fields, locals | `snake_case` | `basis_points`, `transfer_from` |
| Errors, events, variant cases | `Capitalized_snake` or `PascalCase` | `Not_owner`, `Transfer` |
| Modules, interfaces, contracts | `PascalCase` | `Ledger`, `IERC20` |

Error names are converted to PascalCase in the ABI (`Not_owner` becomes `NotOwner()`), so they match Solidity conventions. Two errors whose ABI names would collide are rejected. Function and event names appear in the ABI exactly as written. To match an existing Solidity interface, write `transferFrom`.

## Keywords

These words are reserved:

```text
and as assert at bound call case const contract create defer do else emit end error
errors event external fail failwith false for function if import in indexed interface
is list migrate module nil nonreentrant not of or payable private pure query raises
record requires skip then true type Unit until upgrade upgradeable use var view with
```

`storage`, `transient`, `guard`, `receive`, and `fallback` are keywords only where a declaration expects them, and `delegates`, `forwards`, and `to` only after `fallback`. Elsewhere they are names like any other.
