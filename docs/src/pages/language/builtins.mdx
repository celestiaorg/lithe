# Built-ins

Lithe has no magic globals. Execution context comes from `Evm`, hashing from `Crypto`, and encoding from `Abi`. Every call names where its value comes from, so a search for `Evm.` finds every place a contract depends on its environment.

## `Evm`

Execution context. Readable in `view` and stateful functions, and not in `pure` functions.

### Message

| Built-in | Type | Solidity |
| --- | --- | --- |
| `Evm.sender()` | `address` | `msg.sender` |
| `Evm.value()` | `wei` | `msg.value`. Only in `payable` functions |
| `Evm.calldata()` | `bytes` | `msg.data` |
| `Evm.selector()` | `bytes4` | `msg.sig` |

### Transaction

| Built-in | Type | Solidity |
| --- | --- | --- |
| `Evm.tx_origin()` | `address` | `tx.origin`. Do not use for authorization |
| `Evm.tx_gas_price()` | `wei` | `tx.gasprice` |

### Block

| Built-in | Type | Solidity |
| --- | --- | --- |
| `Evm.block_number()` | `nat` | `block.number` |
| `Evm.block_timestamp()` | `timestamp` | `block.timestamp` |
| `Evm.block_coinbase()` | `address` | `block.coinbase` |
| `Evm.block_base_fee()` | `wei` | `block.basefee` |
| `Evm.block_prevrandao()` | `bytes32` | `block.prevrandao` |
| `Evm.block_gas_limit()` | `nat` | `block.gaslimit` |
| `Evm.chain_id()` | `nat` | `block.chainid` |
| `Evm.block_hash(n : nat)` | `bytes32` | `blockhash(n)` |
| `Evm.blob_hash(i : nat)` | `bytes32` | `blobhash(i)` |

### Accounts

| Built-in | Type | Solidity |
| --- | --- | --- |
| `Evm.self()` | `address` | `address(this)` |
| `Evm.balance(a : address)` | `wei` | `a.balance` |
| `Evm.code_size(a : address)` | `nat` | `a.code.length` |
| `Evm.code_hash(a : address)` | `bytes32` | `a.codehash` |
| `Evm.gas_left()` | `nat` | `gasleft()` |
| `Evm.creation_code(C)` | `bytes` | `type(C).creationCode`, for a contract `C` that [`defer create`](/language/effects#create) can create. Usable in `pure` functions, and its hash is a constant |

### Sending ether

| Built-in | Type | Solidity |
| --- | --- | --- |
| `Evm.transfer(to : address, amount : wei)` | `operation` | `payable(to).call{value: amount}("")` |

`Evm.transfer` builds an operation, so it is only valid after `defer`, in a stateful function: `defer Evm.transfer(to, amount);`. See [Queries and deferred calls](/language/effects#evmtransfer).

### Raw calls

| Built-in | Type | Solidity |
| --- | --- | --- |
| `Evm.call(to : address, data : bytes)` | `operation` | `to.call{value: v}(data)`, with `with value = v` |
| `Evm.delegate_call(to : address, data : bytes)` | `operation` | `to.delegatecall(data)` |
| `Evm.static_call(to : address, data : bytes)` | `bytes` | `to.staticcall(data)` |

`Evm.call` and `Evm.delegate_call` are deferred, and a continuation gets the return data as `bytes`. `Evm.static_call` runs with `query`. See [Raw calls](/language/effects#raw-calls).

Reading `Evm.value()` outside a `payable` function is an error, so a function cannot rely on ether it could never receive:

```lithe rejects
storage is record {
  n : nat;
}

external function go() is {
  const x : wei := Evm.value();
  skip
}
```

```text
external function `go` reads `Evm.value()`; write `external payable function`
```

## `Crypto`

Hash functions and signature recovery. Usable in any function, `pure` ones included.

| Built-in | Type | Solidity |
| --- | --- | --- |
| `Crypto.keccak256(x : bytes \| string)` | `bytes32` | `keccak256(x)` |
| `Crypto.sha256(x : bytes \| string)` | `bytes32` | `sha256(x)` |
| `Crypto.ripemd160(x : bytes \| string)` | `bytes20` | `ripemd160(x)` |
| `Crypto.ecrecover(hash : bytes32, v : nat, r : bytes32, s : bytes32)` | `address` | `ecrecover(...)` |

To hash several values, encode them first: `Crypto.keccak256(Abi.encode(a, b))`.

### Precompiles

Every precompiled contract is a built-in, given its input as the precompile lays it out. Like the hashes, they are usable in `pure` functions.

| Built-in | Type | Precompile |
| --- | --- | --- |
| `Crypto.mod_exp(base : bytes, exponent : bytes, modulus : bytes)` | `bytes`, as long as `modulus` | `0x05`, EIP-198 |
| `Nat.pow_mod(base : nat, exponent : nat, modulus : nat)` | `nat` | `0x05` on words. `Panic(0x12)` if `modulus` is zero |
| `Crypto.bn254_add(a : (nat, nat), b : (nat, nat))` | `(nat, nat)` | `0x06`, EIP-196 |
| `Crypto.bn254_mul(p : (nat, nat), s : nat)` | `(nat, nat)` | `0x07`, EIP-196 |
| `Crypto.bn254_pairing(pairs : list((nat, nat, nat, nat, nat, nat)))` | `bool` | `0x08`, EIP-197. Each pair is `(g1_x, g1_y, g2_x_im, g2_x_re, g2_y_im, g2_y_re)` |
| `Crypto.blake2f(rounds : uint32, h : list(bytes32, 2), m : list(bytes32, 4), t : bytes16, final : bool)` | `list(bytes32, 2)` | `0x09`, EIP-152. `h`, `m`, and `t` hold their little-endian words as the EIP lays them out |
| `Crypto.kzg_point_evaluation(versioned_hash : bytes32, z : nat, y : nat, commitment : bytes, proof : bytes)` | `bool` | `0x0a`, EIP-4844. `commitment` and `proof` are 48 bytes |
| `Crypto.bls12_g1_add(a : bytes, b : bytes)`, `Crypto.bls12_g2_add(a, b)` | `bytes` | `0x0b`, `0x0d`, EIP-2537 |
| `Crypto.bls12_g1_msm(pairs : bytes)`, `Crypto.bls12_g2_msm(pairs)` | `bytes` | `0x0c`, `0x0e`. Each pair is a point, then a 32-byte scalar |
| `Crypto.bls12_pairing(pairs : bytes)` | `bool` | `0x0f` |
| `Crypto.bls12_map_fp_to_g1(fp : bytes)`, `Crypto.bls12_map_fp2_to_g2(fp2 : bytes)` | `bytes` | `0x10`, `0x11` |
| `Crypto.p256_verify(hash : bytes32, r : bytes32, s : bytes32, x : bytes32, y : bytes32)` | `bool` | `0x100`, EIP-7951 |

BLS12-381 points and field elements are `bytes` in EIP-2537's encoding: a field element is 64 bytes, a G1 point 128, and a G2 point 256.

A precompile that rejects its input, such as a point off its curve, reverts the transaction, except where the result is a `bool`: `kzg_point_evaluation` and `p256_verify` answer `false` for a proof or signature that does not verify. The pairings answer whether the product of pairings is one, and revert on malformed input.

Each call also checks the size of the answer. On a chain without the precompile, the call reaches an account with no code, which succeeds with no answer: that reverts, or reads as `false`, never as zeros. `Crypto.p256_verify` answers `false` on chains before EIP-7951.

The identity precompile, `0x04`, copies its input, which a value already is. `query Evm.static_call(to, data)` reaches any precompile directly.

## `Abi`

ABI encoding and decoding. Usable in any function, `pure` ones included.

| Built-in | Type | Solidity |
| --- | --- | --- |
| `Abi.encode(a, b, ...)` | `bytes` | `abi.encode(a, b, ...)` |
| `Abi.encode_packed(a, b, ...)` | `bytes` | `abi.encodePacked(a, b, ...)` |
| `Abi.encode_with_selector(sel : bytes4, a, ...)` | `bytes` | `abi.encodeWithSelector(sel, a, ...)` |
| `Abi.encode_with_signature(sig : string, a, ...)` | `bytes` | `abi.encodeWithSignature(sig, a, ...)` |
| `Abi.encode_call(Interface.method, a, ...)` | `bytes` | `abi.encodeCall(I.method, (a, ...))`. Arguments are type-checked |
| `Abi.decode(data : bytes, T)` | `T` | `abi.decode(data, (T))` |
| `Abi.supports_interface(id : bytes4)` | `bool` | whether `id` is ERC-165's or one `supports` lists, as the generated `supportsInterface` answers. See [ERC-165](/language/modules#erc-165) |

`Abi.decode` takes a type name as its second argument: `Abi.decode(data, nat)`, which decodes one value, as Solidity's `abi.decode(data, (uint256))`. Any ABI value can be decoded; name a list or record type first, as `type ids is list(nat);`, then `Abi.decode(data, ids)`. A tuple of type names decodes one value of each, as `abi.decode(data, (address, uint256))` does: `const (who, amount) : (address, nat) := Abi.decode(data, (address, nat));`. Malformed data reverts, with Solidity's checks on every offset, length, and word.

`Abi.encode` takes any ABI values, each one argument: a record or tuple is a Solidity tuple. `Abi.encode_packed` packs what Solidity's `abi.encodePacked` does: words, strings, bytes, and lists of words, each element padded to 32 bytes. It has no layout for records, tuples, nested lists, or lists of strings or bytes.

```lithe
storage is record {
  digest : bytes32;
}

external function commit(const amount : nat; const salt : bytes32) is {
  storage.digest := Crypto.keccak256(Abi.encode(Evm.sender(), amount, salt));
}

external pure function round_trip(const n : nat) : nat is
  Abi.decode(Abi.encode(n), nat)

external pure function transfer_call(const to : address; const amount : nat) : bytes is
  Abi.encode_with_signature("transfer(address,uint256)", to, amount)
```

## `Bytes` and `String`

| Built-in | Type | Solidity |
| --- | --- | --- |
| `Bytes.concat(a, b, ...)` | `bytes` | `bytes.concat(a, b, ...)`. Arguments are `bytes` or `bytesN` |
| `Bytes.word(b : bytes, offset : nat)` | `bytes32` | the 32 bytes at `offset`. `Panic(0x32)` if they run past the end |
| `String.concat(a, b, ...)` | `string` | `string.concat(a, b, ...)` |

```lithe
storage is record {
  greeting : string;
}

external function greet(const name : string) is {
  storage.greeting := String.concat("hello, ", name, "!");
}

external pure function tagged(const tag : bytes4; const data : bytes) : bytes is
  Bytes.concat(tag, data)
```

`bytes` values index and slice as in Solidity. Each works on parameters, locals, stored values, and call results such as `Evm.calldata()`:

| Expression | Type | Solidity |
| --- | --- | --- |
| `b[i]` | `bytes1` | `b[i]`, for `b : bytes` or any `bytesN`. `Panic(0x32)` if `i` is past the end |
| `b[start:end]`, `b[start:]`, `b[:end]` | `bytes` | `b[start:end]` on calldata: a copy of the bytes from `start` up to `end`. `Panic(0x32)` if `start > end` or `end` is past the end |
| `bytes(s)`, `string(b)` | `bytes`, `string` | `bytes(s)`, `string(b)`, with no copy |
| `bytesN(b)` | `bytesN` | `bytesN(b)`: the first N bytes of `b`, zero past its end. From a `bytesM`, the first N bytes, or all M and then zeros |

A single byte can't be assigned: build a new value from slices with `Bytes.concat`.

```lithe
storage is record {
  forwarder : address;
}

(* ERC-2771: a trusted forwarder appends the original sender to the calldata. *)
external view function msg_sender() : address is {
  const data : bytes := Evm.calldata();
  var sender : address := Evm.sender();
  if sender = storage.forwarder and data.length >= 20n then {
    sender := address(bytes20(data[data.length - 20n:]));
  }
} with sender

(* The payload of a custom error `LowBalance(uint256)`, from its revert data. *)
external pure function low_balance(const reason : bytes) : nat is {
  var have : nat := 0n;
  if reason.length >= 36n and bytes4(reason) = bytes4(Crypto.keccak256("LowBalance(uint256)")) then {
    have := Abi.decode(reason[4n:], nat);
  }
} with have
```

## `Base64`

RFC 4648 base64, with the same algorithm and lookup tables as Solady's `Base64`. Usable in any function, `pure` ones included. `data` is `bytes` or `string`.

| Built-in | Type | Solidity |
| --- | --- | --- |
| `Base64.encode(data)` | `string` | `Base64.encode(data)`: the standard alphabet, padded with `=` |
| `Base64.encode_url(data)` | `string` | `Base64.encode(data, true, true)`: `-` and `_` for `+` and `/`, no padding |
| `Base64.encode_with(data, file_safe : bool, no_padding : bool)` | `string` | `Base64.encode(data, fileSafe, noPadding)` |
| `Base64.decode(data)` | `bytes` | `Base64.decode(data)`: either alphabet, padded or not, and `,` for 63 as in RFC 3501 |

Like Solady's, `Base64.decode` does not check its input: other characters decode to unspecified bytes.

```lithe
storage is record {
  n : nat;
}

external pure function contractURI() : string is
  String.concat("data:application/json;base64,", Base64.encode("{\"name\":\"Badge\"}"))
```

## `List`

| Built-in | Type | Solidity |
| --- | --- | --- |
| `List.push(xs, v)` | statement | `xs.push(v)`: appends `v` to a dynamic list |
| `List.pop(xs)` | statement | `xs.pop()`: drops a dynamic list's last element. `Panic(0x31)` if it is empty |

`xs` is a stored list or a `var`, and `List.push(xs, v);` and `List.pop(xs);` are statements: they write `xs` as an assignment would, so a `view` function cannot push to or pop a stored list. A stored list clears the element's slots. To remove an element from the middle, move the last one into its place first:

```lithe
storage is record {
  ids : list(nat);
}

external function remove(const i : nat) is {
  storage.ids[i] := storage.ids[storage.ids.length - 1n];
  List.pop(storage.ids);
}
```

## `Nat`, `Int`, and `Address`

Constants take their width from the type the context expects. With no expected type, they are 256-bit.

| Built-in | Type | Solidity |
| --- | --- | --- |
| `Nat.max` | `nat`, or the expected unsigned type | `type(uint256).max` |
| `Int.min`, `Int.max` | `int`, or the expected signed type | `type(int256).min`, `.max` |
| `Address.zero` | `address` | `address(0)` |
| `Nat.div_rem(a, b)` | `(T, T)` | `(a / b, a % b)` |
| `Nat.mul_div(a, b, d : nat)` | `nat` | `Math.mulDiv(a, b, d)`: `a * b / d` with the product in 512 bits. `Panic(0x11)` if the result doesn't fit, `Panic(0x12)` if `d` is zero |
| `Nat.mul_mod(a, b, d : nat)`, `Nat.add_mod(a, b, d : nat)` | `nat` | `mulmod(a, b, d)`, `addmod(a, b, d)`, without overflow. `Panic(0x12)` if `d` is zero |
| `Nat.wrapping_add(a, b)`, `Nat.wrapping_sub(a, b)`, `Nat.wrapping_mul(a, b)` | `T`, the unsigned type of both | `unchecked { a + b }` and the like: the result modulo 2^N for `T`'s N bits |
| `Int.wrapping_add(a, b)`, `Int.wrapping_sub(a, b)`, `Int.wrapping_mul(a, b)` | `T`, the signed type of both | the same for signed types, in two's complement |
| `Int.div_rem(a, b)` | `(T, T)` | `(a / b, a % b)`, truncating |
| `Nat.from_bits(i : int)`, `Int.from_bits(n : nat)` | `nat`, `int` | `uint256(i)`, `int256(n)`: the same 256 bits, unchecked. `nat(i)` and `int(n)` check |
| `Nat.to_string(n)` | `string` | `Strings.toString(n)`: an unsigned integer of any width in decimal |
| `Int.to_string(n)` | `string` | `Strings.toStringSigned(n)`: a signed integer in decimal, `-` first when negative |

```lithe
storage is record {
  cap : uint8;
  label : string;
}

external function name(const id : nat) is {
  storage.label := String.concat("token #", Nat.to_string(id));
}

external function reset() is {
  storage.cap := Nat.max;
}

external pure function bounds() : (int16, int16) is
  (Int.min, Int.max)

external pure function elapsed(const later : uint32; const earlier : uint32) : uint32 is
  Nat.wrapping_sub(later, earlier)
```

Here `storage.cap := Nat.max` stores 255, because the target is a `uint8`, and `elapsed(1, 3)` is 4294967294: the difference wraps to 32 bits.

## Conversions

A type name used as a function converts to it: `nat(x)`, `uint8(n)`, `int(n)`, `address(b)`, `bytes20(a)`, `wei(n)`, `timestamp(n)`, and the names of your own nominal types. See [Conversions](/language/types#conversions).
