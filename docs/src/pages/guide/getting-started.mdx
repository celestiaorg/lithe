# Installation and first contract

:::warning
Lithe is in early development and experimental. The language, standard library, and compiler output can change without notice, and neither the compiler nor the standard library has been audited.
:::

## Install the compiler

Install the latest release with the install script:

```bash
curl -fsSL https://lithe-lang.org/install.sh | sh
```

It downloads the compiler for your platform, Linux or macOS on x86-64 or ARM64, checks it against the release's checksums, and installs it to `~/.lithe/bin/lithe`, or `$LITHE_HOME/bin/lithe` when `LITHE_HOME` is set. If that directory isn't on your `PATH`, it adds it in your shell's profile (`~/.zshrc`, `~/.bashrc`, `~/.bash_profile` on macOS, fish's `config.fish`, or `~/.profile`); set `LITHE_NO_MODIFY_PATH=1` to have it print the line instead. Run it again to update. To install a given version, pass it after `-s --`:

```bash
curl -fsSL https://lithe-lang.org/install.sh | sh -s -- 0.2.2
```

Or build a release with Cargo, which installs it to `~/.cargo/bin`:

```bash
cargo install --git https://github.com/celestiaorg/lithe --tag v0.2.2 --locked
```

To build from source, run this from the repository root with a recent stable Rust toolchain:

```bash
cargo build --release
export PATH="$PWD/target/release:$PATH"
```

Check the install with `lithe --version`. Contracts you deploy should be built with a [released compiler](/tooling/cli#releases), so that they can be verified.

Run with no arguments, `lithe` prints its commands. See [Command line](/tooling/cli) for the full list, and [Editors](/tooling/editors) to set up VS Code, Cursor, or Recur.

To prove contracts' specs with [`lithe prove`](/language/verification#proving-specs), also install the [Z3](https://github.com/Z3Prover/z3) solver, which it runs:

```bash
brew install z3        # macOS
sudo apt install z3    # Debian and Ubuntu
```

Or download a release from [github.com/Z3Prover/z3/releases](https://github.com/Z3Prover/z3/releases) and put `z3` on your `PATH`, or set `LITHE_Z3` to its path. Nothing else needs Z3.

## Write a contract

A Lithe file is a contract. Create `counter.lithe`:

```lithe [counter.lithe]
(* Comments are written like this, and they nest. *)

storage is record {
  count : uint;
}

external view function get() : uint is
  storage.count

external function inc() is {
  storage.count += 1;
}

external function dec() is {
  storage.count -= 1;
}
```

A few things to notice:

- **`storage is record`** declares the contract's persistent state. Every contract has one, and every access is qualified as `storage.count`.
- **`uint`** is an unsigned 256-bit integer. `1` is a `uint` literal. Arithmetic is checked, so `dec` on zero reverts with `Panic(0x11)`, the same panic Solidity uses.
- **`external`** puts a function in the ABI. `external view` promises the function never writes, and the compiler checks the promise.
- **`:=`** assigns, and **`+=`** adds to what is there. **`=`** compares.
- A function body is a block `{ ... }` or a single expression.

## Compile

```bash
lithe compile counter.lithe
```

This prints the contract's creation bytecode as hex. Generate its ABI with:

```bash
lithe abi counter.lithe
```

To build every `.lithe` file in a directory into Foundry-style artifacts under `./out`, pass the directory:

```bash
lithe compile src
```

## Deploy and call

The output of `lithe compile` is creation code, so any deployment tool can use it. With [Foundry](https://getfoundry.sh) and a local `anvil`:

```bash
anvil &

KEY=0xac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80
cast send --private-key $KEY --create $(lithe compile counter.lithe)
# contractAddress 0x5FbDB2315678afecb367f032d93F642f64180aa3

cast send --private-key $KEY 0x5FbDB2315678afecb367f032d93F642f64180aa3 "inc()"
cast call 0x5FbDB2315678afecb367f032d93F642f64180aa3 "get()(uint256)"
# 1
```

Calling `dec()` twice from here reverts with `panic: arithmetic underflow or overflow (0x11)`. To test a contract with Foundry or Hardhat, see [Testing](/tooling/testing).

## See what the compiler knows

Because effects are explicit, the compiler can summarize each entrypoint:

```bash
lithe footprint counter.lithe
```

```text
inc   writes: count            during defers: callable
dec   writes: count            during defers: callable
get   reads: count             during defers: callable
```

[Inspecting contracts](/tooling/inspection) covers `footprint`, `abi-tree`, `analysis`, `errors`, and `storage`.
