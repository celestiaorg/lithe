```lithe
import "std/evm";

error Insufficient_balance of record {
  available : wei;
  required : wei;
}

event Withdrawn of record {
  indexed account : address;
  amount : wei;
}

storage is record {
  balances : map(address, wei);
}

external payable function deposit() is {
  storage.balances[Evm.sender()] := storage.balances[Evm.sender()] + Evm.value();
}

external function withdraw(const amount : wei)
  raises Insufficient_balance
is {
  const balance : wei := storage.balances[Evm.sender()];
  assert(
    balance >= amount,
    Insufficient_balance { available = balance; required = amount; }
  );
  storage.balances[Evm.sender()] := balance - amount;
  emit Withdrawn { account = Evm.sender(); amount = amount; };
  defer Evm.transfer(Evm.sender(), amount);
}
```

## Why now

Smart contracts are now written with AI and attacked with AI. In Anthropic's [SCONE-bench](https://www.anthropic.com/research/smart-contracts), AI agents produced working exploits for **51%** of 405 real exploited contracts, and scanning a new contract for bugs cost about **$1.22**.

The bugs that lose the most money are not exotic. In 2024, **access-control flaws caused about two thirds** of smart-contract losses: a missing caller check, an open initializer, an unguarded upgrade. Reentrancy caused under 3%. Lithe turns these conventions into compiler rules, so neither the developer nor the model has to remember them.
