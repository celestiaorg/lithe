# Command line

```text
lithe compile file.lithe
lithe compile directory
lithe abi file.lithe
lithe abi directory
lithe abi-tree file.lithe
lithe footprint file.lithe
lithe analysis file.lithe
lithe errors file.lithe
lithe facets file.lithe
lithe stubs file.lithe Module
lithe storage file.lithe
lithe storage old.lithe new.lithe
lithe upgrade-check old.lithe new.lithe
lithe upgrade 0xProxy file.lithe --migrate name [--impl 0xImpl] --args ...
```

Commands that read one file need a file with exactly one contract. Errors and warnings go to stderr as `line:column: message`. The exit status is `0` on success, `1` on a compile error, and `2` on a usage error.

## Size flags

`compile`, `abi`, `facets`, `footprint`, `abi-tree`, `upgrade`, and `upgrade-check` also take these flags, anywhere after the command:

| Flag | Default | Meaning |
| --- | --- | --- |
| `--size-limit <bytes>` | `24576` | the most runtime code the router or any facet may have |
| `--split <auto\|off\|all>` | `auto` | run exposed modules from their facets when the contract is over the limit, never, or always |
| `--create2-deployer <address>` | `0x4e59b44847b379578588920cA78FbF26c0B4956C` | the `CREATE2` factory facets are deployed through |

See [Contract size limit](/tooling/size-limit).

## Building

### `lithe compile file.lithe`

Prints the contract's creation bytecode as `0x`-prefixed hex, which is ready to deploy:

```bash
cast send --private-key $KEY --create $(lithe compile counter.lithe)
```

A contract over the size limit runs the modules it exposes from their facets. Then it prints a JSON deployment plan instead: each facet's `CREATE2` transaction, then the router's creation code. It also prints a note on stderr. A contract that creates a split contract prints a plan too, because those facets must exist first. See [Deploying](/tooling/size-limit#deploying).

### `lithe compile directory`

Compiles every `.lithe` file under the directory, and writes one Foundry-style artifact per contract to `./out/<file>/<Contract>.json`:

```json
{
  "abi": [ ... ],
  "bytecode": { "object": "0x...", "sourceMap": "", "linkReferences": {} },
  "deployedBytecode": { "object": "0x...", ... },
  "methodIdentifiers": { "inc()": "371303c0" },
  "contractName": "Counter"
}
```

It prints each path it writes. It keeps going after a failing file, reports every failure, and exits `1` if any file failed. Files that define several contracts are fine in this mode.

A split contract's artifact has the whole contract's ABI and a `facets` field listing each facet's module, address, and the selectors the router forwards to it. Each facet is written once, to `./out/facets/<Module>.json`, however many contracts use it.

### `lithe abi file.lithe` / `lithe abi directory`

Prints the Solidity-compatible JSON ABI: functions, events, and errors. Given a directory, it writes ABIs to `./out`.

## Inspecting

These commands summarize what each entrypoint does. See [Inspecting contracts](/tooling/inspection) for their output.

| Command | Shows |
| --- | --- |
| `lithe footprint file.lithe` | one line per entrypoint: reads, writes, events, deferred calls, errors, and reentrancy status |
| `lithe abi-tree file.lithe` | each entrypoint's dispatch path, guards, calls, and effects |
| `lithe analysis file.lithe` | the same facts as JSON, for tools |
| `lithe errors file.lithe` | each entrypoint's errors, and each error's selector, fields, and raisers |
| `lithe storage file.lithe` | the storage and transient layout, slot by slot |
| `lithe facets file.lithe` | the router and each facet: size against the limit, and the entrypoints each runs |
| `lithe stubs file.lithe Module` | the `use Module exposing` block that declares every external a module has |

## Upgrades

### `lithe storage old.lithe new.lithe` / `lithe upgrade-check old.lithe new.lithe`

Compares the storage layouts of two versions field by field, and ends with `compatible` or `incompatible`. See [Upgrades](/language/upgrades#storage-compatibility).

When either version is split, `upgrade-check` also lists the facets the new version uses, and which of them the old version already has. See [Upgrades](/tooling/size-limit#upgrades).

### `lithe upgrade`

```bash
lithe upgrade 0xProxy vault.lithe --migrate init_settings --impl 0xNewImpl --args 30 0xTreasury
```

Prints the `to` address and the calldata for `upgradeToAndCall(newImpl, migrationCall)`, which runs the named migration with the given arguments. Send it with any wallet or tool:

```bash
cast send --private-key $KEY 0xProxy 0x4f1ef286...
```

For a split contract, it prints the deployment plan with an `upgrade` entry holding the proxy's call. Deploy the facets and the router first. `--impl` is optional here: it defaults to the router's `CREATE2` address from the plan.

## Warnings

The compiler warns, but still compiles, when an entrypoint's deferred calls could let another entrypoint re-enter the contract before the transaction finishes:

```text
7:18: warning: `pay` performs deferred external operations and may
be re-entered through `pay`

consider `nonreentrant` if the protocol requires serialized
external-effect execution
```

See [Reentrancy](/language/reentrancy).
